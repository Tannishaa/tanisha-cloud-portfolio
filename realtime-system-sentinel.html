What Building a Packet Sniffer Taught Me About How the Internet Actually Works

Tanisha · Mar 2026 · 6 min read

I have always been a fan of the top-down approach to learning. Give me a compiler and a massive project idea, and I will figure out the underlying theory when something inevitably breaks.

For a long time, my understanding of networking was strictly theoretical. You sit in a computer science lecture, look at a neatly color-coded diagram of the OSI model, and nod along. You learn that TCP is reliable, UDP is fast, and IP addresses are like digital street names. It all sounds very civilized and orderly.

Then I decided to build Sentinel, a real-time Network Intrusion Detection System powered by a Random Forest AI.

To feed the AI, I needed to capture live network traffic. I opened up a terminal, wrote some code to parse raw packets off my Wi-Fi card, and hit run.

↳ Spoiler alert: the internet is not civilized. It is complete, unfiltered chaos.

The Illusion of the OSI Model

When you learn about networking in a classroom, you picture data moving in perfect little envelopes. You imagine a polite handshake where your computer asks a server for a webpage, and the server politely hands it over.

Watching raw packets flood your terminal shatters that illusion instantly. The gap between theory and what actually moves across the wire is enormous.

The Reality of the Wire

When you build a packet sniffer, you realize the internet is just millions of machines aggressively yelling formatted bytes at each other over specific ports. There is no magic. Every single action you take online boils down to source IPs, destination ports, byte counts, and binary flags.

The Anatomy of a Threat

The whole point of Sentinel was to catch bad actors using anomaly-based detection. But an AI model cannot just look at a network and feel that something is wrong. It only understands numbers.

This forced me to get uncomfortably close to the transport layer. I had to rip apart the TCP headers and translate them into a comma-separated reality. If a packet came in with a SYN flag but never completed the connection, I had to extract that exact behavior.

Visualizing a DoS Attack

Suddenly, a Denial of Service attack was no longer just a cybersecurity buzzword. I could literally watch it happen on my screen. I could see an IP address rapid-firing packets with the S0 flag active, completely flooding Port 80, trying to drown the server in fake connection requests.

Taming the Chaos

Catching the packets was just the beginning. I quickly realized that a real intrusion detection system could not just be a single script. It had to be a living, breathing pipeline capable of handling high-speed traffic without crashing.

So, I built a polyglot architecture. Every language had to pull its own weight:

  • The Edge (C++ & Npcap): If you want to catch live network traffic without dropping packets, you need raw speed. C++ ruthlessly stripped the headers off raw sockets at the data-link layer and streamed them forward via TCP.
  • The Brain (Python & Random Forest): Python is the undisputed king of machine learning. It caught the stream from the edge and ran the network features through an AI classifier to instantly spot anomalies.
  • The Memory (Java Spring Boot & MySQL): When the AI found a threat, it needed a rock-solid place to put it. Java provided a highly stable backend to catch those HTTP payloads and lock them securely into a relational database.
  • The Face (React): Security tools are useless if you cannot read them. A React frontend continuously polled the Java server to visualize the network volatility on a live dashboard.

Getting four different languages to talk to each other synchronously across local ports was an absolute integration nightmare.

The Turning Point

That integration struggle changed everything about how I view software engineering.

When you build web apps, you usually live safely in the application layer. You rely on massive frameworks and libraries to handle the dirty work of actually moving your data from point A to point B. You call an API and trust that the internet will just figure it out.

Building Sentinel forced me to look under the hood. You see the raw bytes, the dropped packets, and the sheer volume of background noise that happens just to keep a simple website connected.

I started this project just wanting to build a cool AI security tool. I walked away with a profound respect for the absolute mess of protocols that somehow keeps the modern world running. Theory is great for passing exams. But if you really want to understand the internet, try catching it with your bare hands.
